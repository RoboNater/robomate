## Deviations from the plan

- **Project.** The runs targeted `RoboNater/repo-archive-tool`, a real project (one of the
  #100 GitLab mirrors), not `robomate-glab-sandbox`. The instance, runner and `glab` are the
  ones #69 describes.
- **"Pipelines must succeed" is off** on this project; the plan's baseline has it on.
  `robomate up` reported it as a NOTE (below). CI was still enforced by the workflow
  policy `allow_no_ci: false`, and every merge gate below read `ci: pass` before merge.
- **Merge method.** Policy `merge_method: squash` against project `merge_method: merge`
  with `squash_option: default_off`. Each merge therefore added a squash commit and a
  merge commit to `main`. The merge was bound with `--sha` to the approved head (run 1)
  or the rebased head (run 2), and the MR's recorded `sha` equals that head.
- **Shape split across two runs.** Run 1's reviewer requested changes; run 2's first
  review approved with nonblocking findings only. The stale-base disturbance was made
  in run 2.
- **Operator intervention in run 2.** To land the unrelated change before Alice's next
  gate, the operator suspended Bob's harness during his NONBLOCKING task while MR !3
  was created and merged, then resumed it. The hub did not mark Bob lost. The plan
  says to land the change after approval; in run 1, Alice merged about 20 s after approval,
  so the change was landed during review instead. Alice's next gate after approval
  saw the stale base, which is what the step tests.
