## Defects and follow-ups uncovered

1. **OpenCode 2.4.1 interactive doctor permissions ([#740](https://github.com/RoboNater/robomate/issues/740)):**
   - `doctor_opencode_environment(v2=True)` (`scripts/agent-launcher.py:2369-2376` at `e14a9e9`) sets `{"action": "*", "resource": "*", "effect": "ask"}` and allows only `read`, `glob`, `grep`, `list` on `write_roots`. In live `opencode v2.4.1`, Denise was prompted repeatedly on granted run roots.
2. **OpenCode 2.x interactive doctor effort ([#741](https://github.com/RoboNater/robomate/issues/741), #253 follow-up):**
   - `EFFORT_SUPPORTED` (`scripts/denise.py:36`) omits `"opencode"`, so `resolve_settings()` clears inherited effort and `doctor_opencode_environment()`'s `f"{model}#{effort}"` branch (`scripts/agent-launcher.py:2382`) never runs. Live interactive variant honoring remains unverified (only hand-built `opencode debug config --standalone` parsing was checked); fixing this must stay version-dependent so OpenCode 1.x is unaffected.
3. **Windows Codex MCP probe `cp1252` crash ([#742](https://github.com/RoboNater/robomate/issues/742)):**
   - `doctor_codex_mcp_flags()` (`scripts/agent-launcher.py:2302-2310` at `e14a9e9`) calls `subprocess.run(..., text=True)` without `encoding="utf-8"`, crashing with `UnicodeDecodeError: 'charmap' codec can't decode byte 0x9d` on native Windows. With `PYTHONUTF8=1`, the probe still failed closed (`exit 2`, `retry with --clean-login`); root cause in `codex mcp list --json` under `PYTHONUTF8=1` needs diagnosis.
4. **Windows Codex `--add-dir` rejection & unfinished grant check ([#743](https://github.com/RoboNater/robomate/issues/743)):**
   - Running `doctor --harness codex --clean-login` (with `PYTHONUTF8=1`) on `Liam73` exited immediately with `Error adding directories: Ignoring --add-dir (...) because the effective permissions do not allow additional writable roots. Switch to workspace-write or danger-full-access to allow them.` (`scripts/agent-launcher.py:2762`). Owns finishing the native Windows Codex extra-directory grant check.
5. **AntiGravity (`agy 1.5.18`) on Linux: `settings.json` rewrite & trusted-only docs ([#744](https://github.com/RoboNater/robomate/issues/744)):**
   - On Linux (`gitlab-box`), `agy 1.5.18` rewrote `settings.json` (dropping `toolPermission` and `allowNonWorkspaceAccess`) and outside `touch` succeeded (`exit 0`), whereas on Windows (`Liam73`) outside writes were sandbox-denied (`exit 1`). `docs/user-guide.md:358` should explicitly document Linux (`agy 1.5.18`) as trusted-only.
6. **Non-blocking observations (to triage separately):**
   - On `gitlab-box`, `robomate status` immediately after `robomate up` (`run-linux-1`, before any agent resumed) reported `3 alive` from pre-shutdown heartbeats.
   - `alice-bridge.jsonl` stopped logging after post-join (`03:37:45Z`) despite active `wait_for_event` calls, and `robomate status --activity` displayed two `alice` header lines.
   - In `run-linux-2`, `alice` calling `get_operator_answer` received `requires a worker role` (guide wording in `guides/orchestrator.md:742` vs. worker-only tool).
   - On `Liam73` (native PowerShell), `scripts/start-run.py` did not exit after `robomate down` on `m7-win-1` and required `Ctrl-C`.
