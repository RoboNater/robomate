## Defects and follow-ups uncovered

1. **OpenCode 2.4.1 interactive doctor permissions (`scripts/agent-launcher.py:doctor_opencode_environment` & `scripts/denise.py:EFFORT_SUPPORTED`):**
   - `doctor_opencode_environment(v2=True)` sets `{"action": "*", "resource": "*", "effect": "ask"}` and allows only `read`, `glob`, `grep`, `list` on `write_roots`, omitting `external_directory` (and `edit`/`write`). In live `opencode v2.4.1`, Denise was prompted repeatedly for `Access external directory` on granted roots as well as every shell/edit action.
   - `opencode debug config --standalone` confirmed OpenCode 2.4.1 parses `"model": "opencode/test-model#high"` into `variant: "high"`, while `EFFORT_SUPPORTED` in `scripts/denise.py` still omits `"opencode"`.
2. **Windows Codex MCP probe `cp1252` crash (`scripts/agent-launcher.py:doctor_codex_mcp_flags`):**
   - `subprocess.run([*argv, *flags, "mcp", "list", "--json"], ..., text=True)` lacks `encoding="utf-8"`, crashing with `UnicodeDecodeError: 'charmap' codec can't decode byte 0x9d` on native Windows when `codex mcp list --json` emits UTF-8 bytes.
   - Re-running with `PYTHONUTF8=1` avoided the decode crash and triggered the fail-closed probe (`exit 2`, `retry with --clean-login`).
3. **Windows Codex `--add-dir` rejection (`scripts/agent-launcher.py:doctor`):**
   - Running `doctor --harness codex --clean-login` (with `PYTHONUTF8=1`) printed the `CODEX_HOME=... codex login` notice and then exited immediately with:
     `Error adding directories: Ignoring --add-dir (...) because the effective permissions do not allow additional writable roots. Switch to workspace-write or danger-full-access to allow them.`
   - Consequently, Codex extra-directory writes on native Windows remain unverified until that flag/sandbox interaction is fixed.
4. **Non-blocking observations:**
   - On `gitlab-box`, `robomate status` immediately after `robomate up` (`run-linux-1`, before any agent resumed) still reported `3 alive` from pre-shutdown heartbeats.
   - `alice-bridge.jsonl` stopped logging after post-join (`03:37:45Z`) despite active `wait_for_event` calls, and `robomate status --activity` displayed two `alice` header lines.
   - In `run-linux-2`, `alice` calling `get_operator_answer` received `requires a worker role`.
